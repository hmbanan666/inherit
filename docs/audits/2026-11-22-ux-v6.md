# UX audit for v6: one screen, two tracks (2026-11-22)

> Historical snapshot of `7dae2d5`. Not the current game. The packs it describes stay at `/?packs`. [ADR 0026](../adr/0026-quantity-quests-one-world.md) is the v8 vision.

Scope: an audit only. No product code was changed. Inputs: ADR 0018, `docs/specs/v5-game-packs.md`, `CONTEXT.md`, `apps/web/app` and `packages/sim/src/packs/*` on `main` at `7dae2d5`, the owner's v5 playtest notes, and a headless walk through https://inherit.kosarev.space at 1440×900 and 1280×720. Screenshots are attached to the PR that adds this file.

## Verdict

v5 put the right parts on screen but too many of them at once, and it had no rhythm. Every extra surface competes with the one loop that matters: **read the goal, write a line, press Run, see the world change, celebrate, continue**. v6 keeps that loop and pushes everything else into one side drawer that never moves the main frame.

## What the playtest hit, and where it comes from

| Symptom | Cause in code |
| --- | --- |
| Continue pressed 3–4 times with no visible change | `revealsAfter['bram-loop']` in `workshop/lesson-flow.ts` queues four reveals (coins, Town, letter `tab`, debt). Each takes one Continue on the same solved card (spec rule “one reveal per Continue”). Their effects appear off to the side: a wallet chip, a nav tab, an unread count, a debt chip. |
| Hint text squeezes the top nav | `workshop/Studio.vue` puts `<small class="clock-note">Deploy starts the clock…</small>` inside `header.hud`, next to sections, wallet, debt, settings and history. |
| Too much UI | Workshop header: pack switcher, section tabs (Shed/Town/Inbox/Orders) with `new` and unread badges, coins, debt chip with bank menu, settings, history dropdown, primary button. World: eyebrow + H1 + Live pill + Bram's speech bubble + floor + town + drawer. Dock: “Code workshop” header, goal, `MyLibrary`, file tabs, API tab, editor status line, Checks/Console tabs, collapse toggle. Footer: save, story toast, machine count. |
| Code line highlight flickers during the `onTick` loop | `usePlayback.play` sets `call` for each record at `TICK_MS / (2 × calls)`, then `call.value = undefined` at the end of every tick. `CodeEditor.lightCall` clears and re-sets the decoration each time, so the line blinks about every 125 ms. |
| No pause or speed control | Speed only comes from the local `?speed=` query (`PackStudio.vue`, `useGame`). Nothing on screen. |
| Deploy and `onTick` unexplained | The only explanation is that header `small` note and a starter comment at `bram-loop`. Nothing on the game area shows that a clock is calling the function. |
| Solved moment feels flat (both packs) | `SolvedCard.vue` is a text card pinned to the top-left of the world. It covers the sky and part of the scene, with no motion (screenshot 05). |
| Duplicate and dead chrome (Beginner) | The world repeats the pack title as an H1 under the switcher. A “Lesson 1 of 13” row takes its own band. The checks sit at the very bottom, far from the code (screenshots 02, 06). |
| Hint shifts the editor | `GoalBar.vue` expands inline, so each rung pushes Monaco down (screenshot 03). |

## Element inventory

**Stays on the main frame**

- Top nav: logo, pack switcher, a progress strip (new, replaces “Lesson n of N”), drawer toggle, settings/palette, wide Run/Deploy button at the far right.
- Game area on the left, with a resizer to the editor on the right.
- One-line goal over the editor (≤ 70 chars, no inline expansion), with a `?` button that opens the drawer.
- Monaco with explanatory comments or TODOs at the edit point.
- Compact coloured checks directly under the editor. Runtime errors show here too.
- Playback bar on the game area: Pause/Play and 1×/2×/4×, only in lessons that run a loop or a long watched run.
- Thin status footer: saved state only.

**Moves into the side drawer** (tabs: Learn · Hints · API · Console)

- Theory and the idea of the lesson (Learn).
- Hint rungs, exact line last (Hints).
- API reference with signatures, parameters, returns and an example (API).
- Console output, when a lesson uses `console.log` (Console). A one-line “Console: 3 lines” badge on the checks row opens it.
- Project files, Workshop only, when a challenge has more than one file.

**Goes**

- Workshop: coins, wallet pop, debt chip and bank menu, Town/Inbox/Orders tabs and their drawers, letters and story toast, unread and `new` badges, history/restore dropdown (keep “Run once” as a secondary action of the primary button), `MyLibrary`, machine count, ore types, extra locations, purchases and the factory progression.
- Bram's speech bubble as a separate element. A character line can go into the celebration.
- The world H1 and eyebrow (the switcher already names the pack). The “Live/Ready” pill becomes part of the playback bar.
- The “Lesson n of N” band, the “Code workshop” band and the editor status line.
- Multi-reveal Continue. One Continue per solve, always.

## Lesson anatomy

| Part | Beginner (`beginner`) | Mid (`workshop`) |
| --- | --- | --- |
| Goal | One line over the editor, the visible result (“Light all five lamps”). | One line over the editor, the challenge name and outcome (“Sort parcels by colour”). |
| Theory | Learn tab: 3–5 sentences, one 1–3 line example, one “Got it”. It opens once on the first lesson of an idea. | None by default. Learn tab holds the task condition: input, rules, 1–2 worked examples, edge cases. |
| Code | Starter with an explanatory comment at the edit line. Kinds: write the line, fill a blank, fix the bug, predict then run. | A function skeleton with signature and `// TODO:` comments that say *what*, never the line. No ready-made solution lines. |
| Hints | Hints tab, 2–3 rungs: idea, then shape, then the exact line. | Hints tab, 2–3 rungs: approach, then the API to use, then pseudo-code. No exact solution. |
| API | Hover help. The API tab lists only the functions the pack has shown so far. | API tab is primary: every function with signature, each parameter, return type, what happens on bad input, and one example. Types (`Parcel`, `Place`) are documented as well. |
| Checks | 1–2 checks in plain words, under the editor. | 3–5 checks, including hidden inputs (“works for an empty belt”). Each failing check names the input it failed on. |
| Effect | Always visible in the scene, playback about 2 calls/s. | Visible on the floor. Loop challenges show the playback bar. |
| Length | 2–4 minutes. | 5–15 minutes. |

### Beginner track (proposal, about 48 lessons in 10 units)

1. Calls and strings: `say`, quotes, two calls in order, typo fix.
2. Numbers: `plant(3)`, arithmetic, `console.log` of a sum.
3. Variables: `const`, `let`, reassignment, why `const` refuses.
4. Types and the colon: `: string`, `: number`, `: boolean`; read a red squiggle and fix the type.
5. Return values: `const apples = basketCount()`, using a result, `isRaining()`.
6. Choices: `if`, `else`, comparisons, `&&` / `||`.
7. Arrays: literals, index, `length`, `push`.
8. Loops: `for…of`, counted `for`, accumulate a total.
9. Your own functions: typed parameters, return types, calling one from another.
10. Interfaces and objects: `interface Guest { name: string; seats: number }`, property access, an array of objects, then the fair capstone.

Each unit ends with a short “unit done” beat and adds one permanent thing to the village.

### Workshop challenges (proposal)

One small floor (belt in, two bins, a scale) and typed parcels `{ id, colour, weight, to }`. No money, ore, town, letters or purchases. About 12 standalone challenges, each from a clean floor with a fixed input set plus hidden variants. Examples: count heavy parcels, route by colour, route with a `Record<string, Place>`, find the heaviest, handle an empty belt, the first `onTick` controller, a jam handled with `if`, a small state machine kept in a variable between ticks.

## Focus and motivation

- **Always know where you are.** The nav progress strip shows unit dots and `12/48`. The current unit is highlighted. The showcase card shows the same strip.
- **Short loops.** First visible effect within 30 seconds of opening a lesson. Beginner lessons take 2–4 minutes. No lesson asks more than one new idea.
- **One celebration, one Continue.** The centred card with small confetti (CSS, about 1 s, skipped under `prefers-reduced-motion`) carries one line of reaction and one line of the idea. Enter presses Continue.
- **Calm streak cues, no loss.** A star for solving without hints. A “3 in a row first try” chip on the celebration. Days practised are shown on the showcase only, never as a broken streak (ADR 0008).
- **Visible accumulation.** The Beginner village keeps every change. Unit ends add one landmark. The finish screen shows the whole thing and the idea chips.
- **Natural stopping points.** After each unit the celebration offers “Next unit” and “Stop here”. Resume returns to the exact lesson and draft.
- **No surprises between lessons.** Nothing new appears on the frame after Continue except the next lesson. Tools appear in the drawer with a dot on its tab, never as new nav items.

## Ordered changes for the implementer

1. **ADR 0019 “One screen, two tracks”.** It replaces from ADR 0018: the solved card placement, reveals per Continue, Workshop sections, coins and debt, the 13-lesson Beginner pack and the v4 Workshop port. It also replaces ADR 0013's economy and ADR 0003's debt, and updates the v5 spec or adds a v6 spec. Name the save policy: v5 Workshop saves are archived under ADR 0004, and Beginner saves map lesson ids where they still exist.
2. **Framework lesson fields** (`packages/sim/src/framework`): add `unit`, `kind: 'write' | 'fill' | 'fix' | 'predict'`, `theory?: { title, body, example }`, `task?: { condition, examples }`, and per-check `input` labels. Drop `reveals` and `release` from the lesson contract. Extend pack validation: Learn text length, a TODO at the edit for mid packs, and no exact-line hint for mid packs.
3. **Single Continue.** In `PackStudio.vue` and the Workshop studio, Continue always opens the next lesson. Delete `revealsAfter` and the `pendingReveals` handling once Workshop is rebuilt (step 9). Until then, drain all pending reveals in one Continue.
4. **`CelebrationOverlay.vue`** replaces `SolvedCard.vue`: centred over the game area, confetti, star and in-a-row chip, Continue focused and bound to Enter. Keep `data-testid="solved-card"` and `continue`.
5. **`SideDrawer.vue`** with Learn/Hints/API/Console tabs, absolutely positioned inside `.world-shell`, with no grid changes. `GoalBar.vue` becomes one fixed-height line with a `?` button. Move hint rungs and `ApiReference.vue` into the drawer. Run closes the drawer. Add test ids `drawer` and `drawer-<tab>`.
6. **Trim the frame.** Remove `.world-title` (H1, eyebrow, Live pill), `.dock-header`, the editor status line and footer extras. Add `ProgressStrip` to `PackNav`. Checks stay under the editor, directly below the last line of the editor host, not pinned to the dock bottom.
7. **`PlaybackBar.vue`** on the game area: Pause/Play, 1×/2×/4×, `onTick #n` counter, Stop loop. Move speed from the query string into studio state. Keep `?speed=` for tests as the initial value. `usePlayback.wait` honours pause.
8. **Steady highlight in loops.** In `usePlayback.play` for `mode === 'tick'`, keep the last call until the next tick instead of clearing it. In `CodeEditor.lightCall`, in live mode mark the lines that ran in the last tick with a steady gutter bar, and do not clear and re-add per call. Watched runs keep the per-call highlight.
9. **Rebuild `workshop`** as the challenge pack in its folder. Delete `Studio.vue` extras (sections, wallet, bank, history, letters, toast, `MyLibrary`), `campaign*`, `town*`, `prices.ts`, `catalog.ts`, `construction.ts`, `story.ts` and the v4 importer after tracing callers. Use the standard `PackStudio` with a `clock`. Document every API function with JSDoc `@param`, `@returns` and `@example` so the API tab can render them.
10. **Explain the loop on screen.** The first `onTick` challenge opens Learn with a three-frame strip (“Run: your code once” / “Deploy: the clock calls `onTick` again and again” / “Stop: the clock stops”). The playback bar's `onTick #n` counter makes the repetition visible. Keep the wide primary button. Its label goes Run → Deploy, and Stop loop while live.
11. **Rewrite `beginner/lessons.ts`** into the 10 units above (split per unit file). Add API functions only as units need them (`basketCount`, `guests()` returning `Guest[]`).
12. **Finish screen.** `PackFinish.vue` moves its stats and idea chips into the editor column. The world stays visible. The primary button becomes “Next pack →”.
13. **Tests.** Update `tests/e2e` for one Continue per lesson, drawer not shifting the layout (compare the editor and world bounding boxes with the drawer open and closed), pause and speed, and steady highlight (no decoration removals between ticks). Capture `start`, `learn`, `running`, `solved` and `finished` frames per lesson under `INHERIT_SHOTS`.

## Friction

1. **Abnormally long:** nothing over a few minutes. About 2 minutes went to installing a throwaway Playwright and Chromium in `/tmp` because the checkout had no `node_modules`.
2. **Hacks:** screenshots came from a standalone Playwright script outside the repo, pointed at production, instead of `tests/e2e/chapter-capture.ts`. The repo route needs install, build and a loopback server first. Production ignores `?lesson=` (`local` gate in `PackStudio.vue` and `app.vue`), so the `bram-loop` state (four Continues, the header clock note) could not be captured without playing about 10 Workshop lessons. It is cited from code instead.
3. **Broken or misleading tooling:** the cloud snapshot runs Node 22.23 while `AGENTS.md` and `.nvmrc` require Node 24. `node_modules` was absent, and `/tmp/cursor/async-install/` had neither status nor log, so no setup ran. `AGENTS.md` asks for the full check suite before any PR, with no docs-only exemption. It was not run here because no product code changed and no dependencies were installed.
4. **2× faster next time:** bake Node 24, `pnpm install` and Chromium into the environment snapshot. Add a `pnpm shots --url <site> --pack <id> --lesson <id>` script that reuses `chapter-capture.ts` against a given URL. Allow `?lesson=` on production behind a non-persisting preview slot (it already uses `.preview.<lesson>`), so audits can open any lesson directly.
