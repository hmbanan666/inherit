# Kettlewick Works UX audit · 24 November 2026

Keep the desk. The villager belongs beside the floor, the code belongs below it, and Tests belongs beside the code. The biggest gains come at the moments when a player has to decide what to do next. A full cart can still earn a prompt to run the same function again. A lit Loop switch can coexist with a program that has no deployed tick function. Both can be explained where the player is already looking.

This is a source walkthrough of `main` at `c700c54`. It covers the single game at `/`, from opening a save through handing over a quest. Layout risks below come from CSS dimensions. Actual clipping, legibility and pointer feel need a playtest. The design baseline is the [glossary](../../CONTEXT.md), [desk layout](../specs/v8-screen-layout.md), [trigger and inspector design](../adr/0025-functions-with-triggers.md), [quantity quests](../adr/0026-quantity-quests-one-world.md), [depot and shop rules](../adr/0027-shop-veins-one-delivery.md), [unlock order](../adr/0028-run-to-completion.md), [one-tick functions and machine tasks](../adr/0029-pure-functions-machine-tasks.md) and [one-home decision](../adr/0030-packs-removed.md).

## A. Problems by screen and area

1. **Choosing a request.** Handing over Bram and Ines gives 40 XP, enough for level 3. Elsie can now be taken before Odile. Elsie tests whether drone-2 left the depot. Odile gives that drone on hand-over. During uninterrupted play the player can accept a quest they cannot finish or switch away from. Reloading a later quest has a separate drone repair. Even before taking a quest, previewing one villager hides the list with no way back to compare offers. 2. **Bram’s first run.** On Take, the usual `main.ts` gains a runnable `haul` example. Calling it once can send drone-1 to Vein A. While the drone walks, mines and finally sits full, the card can keep saying “Press ▶ next to haul”. Its definition of an untouched works reads furnace stock, production and shipments. It never reads the cart. Running the example again cannot unload it. Later, any steel at the furnace takes priority in the hint, even on an ingot request. 3. **Ines and the Loop switch.** Taking Ines can turn Loop on immediately. Her example is inserted as an edit in the open file. Accept sends no code to deploy. A player can see the lit switch while the old program has no `onTick` and sits idle each tick. If a helper was open, the example can also land in `lib/` while the switch looks for the export in `main.ts`. The square on the switch tells the player how to stop, but gives little help getting started. 4. **Stock, delivery and the quest card.** “Ingots 0/2” counts goods claimed by the order. The furnace may already hold two. After Collect, the cart can carry them and the depot can return to zero as the order fills. All three readings are accurate. The bare quantity leaves the player to work out what moved. On Odile’s card, alloy and drone-2 also share the reward strip, although one arrives on Take and the other on Hand over. 5. **Machines and object details.** A floor click opens the same inspector as the Machines list. This is a good place for manual controls. Several rows work against it. Recipes look like disabled purchase buttons. Smelt is enabled at zero ore and can only refuse. Unload says `station` although the cargo determines the destination. “Hauling” draws a bar set to zero for the entire task. A second drone makes it especially important to know that furnace Collect dispatches drone-1. 6. **Map and floor.** The opening drone stands on the depot. The sprite gets first pick, then the cell lookup checks the drone before the building. A player clicking the depot tile can keep opening drone-1. Machines is the reliable alternative. On the floor the same iron-ingot drawing signals either finished ingots or steel. In the list, the furnace summary omits steel and coal. Odile’s steel is easiest to identify by opening the furnace details. ## C. Information architecture

| Player question | Where it lives now | Where it should live |
| --- | --- | --- |
| What can I take? What earns the reward? | Request list → preview → card. Unlocks and gifts share a strip. | Same rail, with a way back, requirements at selection, and timing on reward tiles. |
| What have I delivered? Where is the rest? | Card counts shipments. The floor signals cargo and output. Exact stock is in Machines. | Shipped count on the card, material on the sprite, exact local stock in the inspector. |
| What can this machine do now? | Recipes and commands use the same button style in its inspector. | Recipe among the facts. Commands below, with actor, destination and reason. |
| Can I afford this? | Balance and level in the nav. Price and effect in Shop. | Permanent balance in the nav. Purchase, shortfall and ownership on the shop row. |
| Which code will run? | Tabs show edits. The toolbar deploys and toggles Loop. The gutter runs an export. | Same controls. Show the deployed state at the action that will use it. API help opens on the relevant entry. |
| Why is hand-over blocked? Where did my code fail? | Tests and Console share a pane. The footer opens filtered problems. | Quest footer leads to the remaining test. Console owns errors and source jumps. Status shows script state. |
| Where do I inspect history or reset? | Settings opens Charts under the editor and confirms Start over. | Keep both entries. Close Charts locally. Show restore status on the rail where the next quest normally appears. |

## D. Top 10 by player impact

1. **Prevent the missing-drone quest (B1).** A valid-looking choice can strand a whole session.
2. **Guide the full cart home (B2).** The first quest should teach the difference between a finished call and a drone with work left to do.
3. **Explain a lit but idle Loop (B3).** The first automation unlock is exactly when a player needs to trust the switch.
4. **Name delivered goods (B4).** One label explains how the furnace can be full with zero delivered, and the depot empty with two delivered.
5. **Make the gutter promise match the click (B7).** Running one export can replace a deployed program and cancel another drone’s task.
6. **Put the feasible command on the machine (B5).** A manual player can complete the first production cycle with fewer refused actions.
7. **Keep editor actions in reach (B8).** A narrow code column affects every edit and deploy on a smaller desk.
8. **Jump from a failed deploy to its line (B11).** A player can fix the file directly and tell a script failure from a save failure.
9. **Explain a full order with an open check (B10).** One click takes the player to Wen’s actual requirement.
10. **Make the depot selectable under a drone (B6).** The first place a player needs to inspect is also the first shared tile.
