# Game packs on one framework

Nick played chapter one and missed the change from calling a function to handing it to the clock. Coins and debt arrived before he cared about them. We will ship a showcase of finite game packs. Pick a pack by level (Beginner, Basics, Game or Advanced), setting, learning goals and estimated minutes. Each has a title, tagline and cover. Start several, switch between them and finish each at your own pace.

**One framework.** Write TypeScript, press Run and watch something happen. The framework owns the showcase, switcher, menus, palette (ADR 0006), resizable game area on the left and highlighted Monaco editor on the right. The game stays visible. The wide primary button goes at the far right of the top navigation. The footer carries status only. A watched Run plays one call at a time against its source line (ADR 0014). During playback the button shows why it is disabled. A pack can introduce a clock and Deploy.

**One folder per pack.** The pack declares its manifest, entity schema, initial world, typed player functions with one-line hover help, world view and ordered lessons. Its functions change its world and can return values. Its view draws the state and call log sent by the worker. The framework supplies the QuickJS runner, player declarations for Monaco and generic panels. All resources, people, counters and money belong to packs. The frame has no built-in currency, bank, inbox or order book.

**One idea per lesson.** Put a one-line goal above the editor (up to 70 characters). Explain the idea in starter comments beside the lines to write. Offer hints in rungs, with the exact line last. Pure checks use world state, calls, Console output or, when needed, the program text. The compact checks under the editor turn red, amber and green and collapse when all pass (ADR 0012). Every solution has a visible effect. Over the world, a solved card gives one reaction, what the player did and the idea learned. Only Continue moves on. Release at most one new thing per Continue.

**Show tools when they help.** The first Beginner lesson has the village, goal, one file, Run, checks and Hint. Each pack reveals the Console, file tree, API reference and its own sections when needed. A released section or panel appears only when it has content. Keep the calm pace of ADR 0008. No timers on goals, day counter or pressure. Coins and speed controls stay hidden unless the pack calls for them.

**Two packs.** The showcase highlights the Beginner pack with “Start here”. A friendly villager stands in a tiny village at dawn, all visible at once. In 13 lessons (30–45 minutes) the player goes from a single call to numbers, variables, expressions, functions, parameters, returns, choices, loops and arrays, then uses them to decorate a fair. Errors point out an unknown name, a likely typo or a missing quote in plain words. The village keeps what the player made. One file, global functions, no imports, exports or clock. Workshop is the v4 chapter, level Game, marked “After the basics”. Keep Bram, the arm, furnace, town, letters, orders and deed. Give the move into `onTick` its own commented edit and explain the change from Run to Deploy on screen.

**Save and extend.** Keep a versioned localStorage slot per pack id. Migrate the v4 chapter into Workshop with its progress and code. Discover packs by folder. Validate every manifest, unique lesson id, short goal, adjacent comment, player wording and level restrictions. Each starter must compile and leave the lesson unsolved. Each reference solution must compile and pass on the real runner. Play every pack through the browser and capture its world under `INHERIT_SHOTS`. Keep test ids and the local pack, lesson and speed selectors. Ship a passing `pnpm new-pack <id>` scaffold, reusable visual parts, an authoring guide and an author-pack skill. Future packs about a clock and modules, strategy, farming, React or signals should need only a new folder. Remove unused v2 code after tracing callers. Pin Node 24 and run the checks in CI on pull requests and pushes to main.

**Earlier decisions.** This replaces the single-town premise of ADR 0001. Kettlewick still gives Workshop requests their meaning. ADR 0003's debt subject and ADR 0013's coins, orders and factory progression belong to Workshop alone. ADR 0008 already removed deadlines and interest. ADR 0005 and ADR 0011 now disclose tools per pack. This replaces the footer button in ADR 0011 and ADR 0014, and the multi-line task above the editor in ADR 0015. The sim still owns lesson flow. ADR 0016 is a direction a village pack may take. ADR 0017 still governs the Workshop clock. ADR 0004's archive policy covers older incompatible saves. A valid v4 chapter resumes.

The [implementation spec](../specs/v5-game-packs.md) gives the pack contract, full lesson sequence, Workshop port and validation rules.
