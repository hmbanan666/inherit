# Inherit v8: the inherited works

Status: concept, accepted 23 November 2026 ([ADR 0021](../adr/0021-v8-inherit-a-factory.md)). The first playable slice is planned in [the v8 spec](../specs/v8-first-playable.md). Numbers below are starting values for tuning, not balance.

## Why

v5 to v7 turned the game into a course: packs, lessons, step cards. It became a heavy textbook and lost the game. The early prototypes (v1, v2) felt like a game: ticks, a CPU budget, you write code and the world answers. v8 goes back to that and keeps what we learned since: the frame, Monaco, plain-word errors, readable API cards.

## One sentence

You inherit Uncle's factory, Kettlewick Works, with code that works but is slow, CPU-hungry and fragile; you fix it, write your own code on top and fill orders before the money runs out, while veins run dry and the world keeps changing.

## The loop

1. **Read and Run.** The world runs on ticks. Your `onTick` runs every tick inside a CPU budget.
2. **Watch.** Numbers tell you what your code costs and earns: CPU per tick, credits, rent, throughput, orders due.
3. **Something breaks or runs out.** A vein empties, an order needs something new, rent goes up, an API changes.
4. **Rewrite.** Fix Uncle's code, extract helpers, add new automation. Good code pays off at once in the numbers.
5. **Earn and unlock.** Filled orders pay credits. Credits buy API versions (new bricks), stations, drones and CPU.

The rhythm is write, watch for 5 to 10 minutes, react. Each problem is new, not the same one bigger.

### Three layers of play

- **Inherited core.** Uncle's `main.ts` runs from the first tick. It is correct enough to earn a little, and wasteful everywhere. Improving it is the first thing to do and stays rewarding all session.
- **Your code.** Helpers, files, small abstractions. Over sessions it becomes your framework (`lib/`), which you carry to the next inheritance.
- **The world.** Orders with deadlines in ticks, finite resources, rent, a market. This is why the code matters.

## Not idle, and near real time

- **Everything is finite.** Veins hold a fixed amount of ore. New veins are farther, shaped differently or impure. Rent for drones, stations and CPU is charged every tick, so wasteful code burns money and bad code can bankrupt the works.
- **Tick of 0.5 s at 1x**, speeds 1x, 2x, 4x. Results show seconds after Run.
- **A session is 20 to 40 minutes** at normal play: the inheritance, two or three crises, the audit. It ends on an audit tick or on bankruptcy, with a result screen.
- **The world pauses when you leave** (tab hidden or Pause). Nothing farms while you are away. There are no wall-clock timers; deadlines are counted in ticks and shown as "due in 120 ticks".

## Resources

| Resource | Where it comes from | What it is for |
| --- | --- | --- |
| Credits | Orders, market sales | Rent, unlocks, market purchases |
| Ore | Veins, mined by drones | Smelted into ingots |
| Slag | Impure veins | Waste. Jams the furnace unless sorted out |
| Ingots | Furnace, 2 ore to 1 ingot in 4 ticks | Orders, market, later parts |
| CPU | Rented per tick, in tiers | Every API call costs CPU |
| Memory | `memory` object kept between ticks | Caching paths, plans and state. Size-limited |

Starting values: 300 credits, CPU limit 30 per tick, 3 drones, 1 furnace, vein A (800 ore, 6 cells away), vein B (1200 ore, 14 cells away). Rent: drone 1 cr per 10 ticks, furnace 2 cr per 10 ticks, each extra 10 CPU 3 cr per 10 ticks.

## CPU

- Each API brick has a fixed CPU cost (reads are free, actions cost 1, path finding 3, scan 10). Costs are listed on the API cards and in hover help.
- When `onTick` spends its limit, the rest of the tick is skipped. The world shows it: the drones that got no command stand still, and the Console names the line where the limit was hit.
- The guest wall-clock cap (25 ms) and memory limit of the sandbox stay as safety nets. They are not gameplay.
- Later: an unused-CPU bucket for bursts, CPU cost of plain guest computation (deterministic instruction count).

## Starter API (v1.0)

Imported from `"inherit"`. Cards are generated from the brick registry with signature, one line, example, CPU cost and the API version that added it.

| Brick | CPU | Meaning |
| --- | --- | --- |
| `onTick()` (you export it) | | Called every tick |
| `tick` | 0 | Current tick |
| `credits()` | 0 | Current credits |
| `cpu.used()`, `cpu.limit` | 0 | CPU spent this tick and the limit |
| `memory` | 0 | Object kept between ticks |
| `drones()` | 0 | Your drones: `pos`, `cargo`, `capacity`, `name` |
| `veins()` | 0 | Known veins: `pos`, `left`, `name` |
| `furnace` | 0 | `pos`, `input`, `output` |
| `orders()` | 0 | Open orders: `item`, `qty`, `due`, `pay`, `from` |
| `findPath(from, to)` | 3 | Path as a list of cells |
| `drone.moveAlong(path)` | 1 | One step along a path |
| `drone.isNear(target)` | 0 | Adjacent to a vein or station |
| `drone.mine(vein)` | 1 | Mine 1 ore into cargo. Throws on an empty vein |
| `drone.unload(station)` | 1 | Unload cargo into a station |
| `furnace.smelt()` | 1 | Smelt one batch. Burns fuel (1 cr) even when empty |
| `ship(order, qty?)` | 1 | Ship ingots towards an order |
| `log(...values)` | 0 | Console line with the source line |

## API versions and the changelog

The API itself is part of the world. It grows in versions the player buys or receives, each with a changelog card:

- **v1.1** `scan(range)` finds unknown veins (CPU 10).
- **v1.2** `market.sell(item, qty)`, `market.buy(item, qty)`, `market.price(item)`.
- **v1.3** `drone.drill(vein)` returns `{ ore, slag }` and handles impure veins; `drone.mine` is deprecated (struck through by Monaco through `@deprecated`, still works, then stops in v2.0).
- **v1.4** `build(kind, pos)` and `release(station)` to rent and stop renting stations; new station `sieve`.
- **v2.0** Breaking: `mine` removed. A migration the player does on his own code, like at work.

## Unlock curve

Credits buy, roughly in this order: one more drone, CPU tier +10, v1.1 scan, v1.2 market, v1.3 drill, a second furnace, v1.4 build and the sieve, press and wire orders. Every unlock answers a problem the player has just met. There is no research tree; the unlock list shows only what is affordable soon.

## The first 30 minutes

**0:00. The inheritance.** One line on screen: "Uncle Ambrose left you Kettlewick Works. The code runs. Mostly." The map shows the depot, the furnace, three drones, vein A nearby and vein B far at the edge. The editor shows Uncle's `main.ts`:

```ts
// Kettlewick Works. It works. Don't touch it. - Uncle Ambrose
import { drones, veins, furnace, orders, ship, findPath } from "inherit"

export function onTick() {
  for (const drone of drones()) {
    // find the nearest vein. Every tick, for every drone.
    let best = veins()[0]
    for (const v of veins()) {
      if (findPath(drone.pos, v.pos).length < findPath(drone.pos, best.pos).length) best = v
    }
    if (drone.cargo < drone.capacity) {
      if (drone.isNear(best)) drone.mine(best)
      else drone.moveAlong(findPath(drone.pos, best.pos))
    } else {
      if (drone.isNear(furnace)) drone.unload(furnace)
      else drone.moveAlong(findPath(drone.pos, furnace.pos))
    }
  }
  furnace.smelt()                      // even when empty
  for (const o of orders()) ship(o)    // first come, first served
}
```

**0:01. Run.** Drones move, ore flows, the first ingots appear. The nav shows CPU 30/30 in red. Drone 1 works; drones 2 and 3 never move. The Console says: "CPU limit hit at line 9. drone-2 and drone-3 got no command this tick." Rent is higher than income: credits slowly fall.

**0:03 to 0:08. First fix.** The player computes the path once and keeps it in `memory`, or drops the nested loop. CPU falls to about 10, all three drones work, income passes rent. The nav shows the change after the next Run: "-20 CPU, +0.4 ingots per 10 ticks".

**0:08 to 0:12. Two orders.** Mayor Hale wants 20 ingots due in 300 ticks; the smithy wants 10 due in 150. Uncle ships first come first served, splits the ingots and both go late. Late orders pay half. The player sorts by `due`. Also `furnace.smelt()` on an empty furnace burns 1 cr each tick; a one-line `if` stops it.

**0:12 to 0:15. Crisis: vein A runs dry.** `drone.mine(best)` throws on the empty vein, `onTick` stops, all drones freeze while rent keeps running. Plain error under line 12: "Vein A is empty. `mine` cannot take ore from it. Check `vein.left` first." The player skips empty veins and sends drones to vein B, 14 cells away. Round trips double, so ingots per tick halve: buy a drone, or think about who goes where.

**0:15 to 0:22. Scan and impure ore.** With saved credits the player buys API v1.1. `scan(20)` finds vein C, close but 40% slag, which jams the furnace. The changelog offers v1.3 with `drill`, which separates slag, and marks `mine` deprecated. The player migrates the call and watches the strike-through disappear.

**0:22 to 0:30. Crisis: demand shift.** Ingot prices drop; the new orders want wire, which needs a press. Rent a press (higher rent) or buy wire on the market (v1.2) and keep mining. Either way the controller grows: the player has `findVein`, `assign`, `deliver` helpers in his own files.

**About 0:35. The audit.** The session ends on the audit tick (or earlier on bankruptcy). The result screen shows credits, orders on time, average CPU per tick, CPU per ingot, Uncle's lines still running and the player's own lines. Files in `lib/` are kept for the next inheritance.

## Crises

Each crisis is a content module with a trigger, an effect, a plain message and the bricks it calls for. The first slice ships only "vein runs dry".

- Vein runs dry (finite ore).
- Impure vein (slag jams the furnace).
- Rush order (short deadline, high pay).
- Rent hike for CPU or stations.
- Demand shift (a new item is wanted, the old one sells cheap).
- Drone wear and breakdown (needs `repair`).
- Power dip (CPU limit halved for N ticks).
- API deprecation and a breaking version.
- Market crash or ore shortage.
- Memory limit reached.
- Later: a rival works on the same market and buys the same ore.

## Learning, hidden inside

- API cards with an example and the CPU cost; hover help in Monaco.
- Plain-word compile and runtime errors under the line (the v7 translator stays and gains runtime cases).
- Hints come from the world: the foreman notes what the numbers show ("drone-3 has not moved for 40 ticks"). Later an AI agent in the world can answer questions through MCP.
- No lessons, step cards, prefill or solved cards. Optional side contracts may use the self-contained exercise format of ADR 0020 (one goal, visible tests) for small pure-function tasks; they are not the core loop.

## What is cut from v7

- Packs, the showcase, the Beginner course (52 lessons) and the 12 Workshop challenges as the product.
- Step cards, decreasing prefill, solved card with Continue, course map chip, Learn drawer.
- Watched Runs that replay one call at a time; Run deploys onto the live clock.
- The no-pressure rule of ADR 0008: v8 has deadlines in ticks, rent and bankruptcy.

The pack code stays in the repository until the first v8 slice is live, then it is removed in its own PR.

## What stays

The frame: top nav, charcoal palette (ADR 0006), game area on the left and Monaco on the right, wide Run at the top right, compact coloured status under the editor, no wall-clock timers. QuickJS sandbox with multi-file projects and source maps, the worker that owns the simulation, plain-word errors, API cards generated from one registry (ADR 0009), versioned saves and the archive policy (ADR 0004).

## Architecture: a fixed core, content as modules

New code lives in `packages/sim/src/v8/` until the packs are removed.

- **Core** (`core/`), changed rarely: deterministic tick loop with a seed, world store of entities with positions, the CPU meter, the ledger (credits, rent, income), order book, event and message queue, session clock (audit tick, pause), save and migrate.
- **Bricks.** One registry entry per API call: name, TypeScript signature, one-line doc, example, CPU cost, `since` version, optional `deprecated: { since, use }`, `removed` version and a handler on the world. Declarations for Monaco, API cards and the changelog are generated from it.
- **Modules** (`modules/`), where the game grows: `defineModule({ id, version, entities, bricks, crises, orders })`. Examples: `mining` (drones, veins, mine), `smelting` (furnace), `orders`, `market`, `scan`. A new feature is a new module or a new module version, not a new game.
- **Crises**: `{ id, when(world), apply(world), message }`, owned by modules.
- **Site** (`sites/`), pure data: map, starting entities, inherited files, enabled modules, API version and unlock prices, order schedule, crisis schedule, audit tick. The first site is Kettlewick Works.
- **Saves**: `{ schema, site, modules: { id: version }, tick, seed, world, files, lib }`. Each schema bump ships a migration; unknown saves are archived and start fresh (ADR 0004). The player's `lib/` files survive everything.
- **Web**: the worker runs the core and the sandbox; the page renders the world snapshot on a plain 2D grid (squares and labels are enough for the slice), the nav meters, the orders strip, the Console and the API cards.
