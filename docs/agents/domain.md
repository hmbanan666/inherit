# Domain docs

Before exploring a change, read the root `GLOSSARY.md` if present and any relevant architecture decision records in `docs/adr/`. These documents apply across the workspace. If they do not exist yet, continue with the task.

Use glossary terms in tickets, code, and tests. Use `domain-modeling` to record terms and decisions as they are settled. If a proposal conflicts with an existing decision, cite the ADR and explain why it should be revisited.
